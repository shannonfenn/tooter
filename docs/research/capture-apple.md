## 2. Ranked recommendation

**#1 — Flow A: Action-Button document-scan Shortcut saving into an iCloud-synced inbox.**
It is the only flow that hits ≤2 manual actions *with scan-grade output*, which prior research established as the lever against the dominant VLM failure modes (blur/rotation). The capture itself is well inside 30 s; the only threat to the budget is iCloud propagation, which is usually seconds on a healthy LAN but documented only as "within a couple of minutes" (Eclectic Light, Apr 2026). Since the Mac folder is read **on-demand** (not file-watched), the consuming command absorbs this: it should (a) list the folder, (b) `brctl download` anything dataless, (c) optionally wait/retry briefly for a just-scanned page. **Decision rule: if empirical sync-latency tests (checklist §5.1) show p90 > ~60 s on your LAN, promote #2 to primary.**

**#2 (fallback, and best zero-setup option) — Flow B: Finder "Import from iPhone → Scan Documents" directly into `~/studies/inbox/`.**
Identical scanner and output quality, file lands **locally and deterministically** (no cloud in the loop), works even if iCloud is misbehaving. Costs one extra Mac-side action (or a fragile hotkey macro). This is also the right flow to use *today*, before any setup.

**#3 — Flow C (desk-stand Continuity Camera + CLI grab)** only as an experiment: it wins on friction (1 action, phone untouched) but loses on the dimension that matters most — image quality (1920×1440 video-grade, no deskew). Worth one empirical session to see if Claude reads your handwriting at ~170 dpi with ImageMagick post-processing; do not build on it first. Desk View specifically is **not** suitable: same 1920×1440 ceiling, synthesized warp, and reviewers report text is barely usable ("don't expect wonders").

Flows D and E are dominated: more taps (D) or worse latency variance (E), and both deliver unprocessed photos — the exact failure mode you're avoiding.

## 3. Flow details and evidence

### Flow A — Action Button → scan → iCloud Drive inbox

**Documented facts.** iPhone 16 Pro's Action Button can run any shortcut (Settings > Action Button → swipe to Shortcut) — [Apple: Use and customize the Action button](https://support.apple.com/guide/iphone/use-and-customize-the-action-button-iphe89d61d66/ios), [Apple: Run shortcuts with the Action button](https://support.apple.com/en-om/guide/shortcuts/apdfea15680b/ios). A **native "Scan Document" Shortcuts action exists since iOS 17 beta** ([Automators forum, Jun 2023](https://talk.automators.fm/t/app-or-shortcut-for-scanning/15937)). Its two documented quirks: it "opens the Scan Document interface — **which scans into the current Files folder** — then waits for you to return to Shortcuts before retrieving the file" ([Cassinelli's Scan Documents shortcut](https://matthewcassinelli.com/shortcuts/scan-documents/)), and it "doesn't allow you to do much with that scanned item as a variable" ([HeyDingus](https://heydingus.net/blog/2024/8/simple-scan-aped-my-shortcut)). The scanner itself auto-captures pages in Auto mode and supports Color/Grayscale/B&W ([Apple: How to scan documents on your iPhone](https://support.apple.com/en-us/108963); [MacRumors Files-app scan guide](https://www.macrumors.com/how-to/scan-documents-ios-files-app/)). Note iOS 18 changed the default to full-color scans with much larger PDFs — set Grayscale/B&W for math pages ([MacObserver](https://www.macobserver.com/tips/how-to/large-document-scans-ios/)).

**Two build variants** (both end with a PDF/images in `iCloud Drive/studies/inbox`):
- *Native-only*: single "Scan Document" action; because output isn't a usable variable, either accept its scans-into-current-Files-folder behavior (make the inbox that folder), or use Cassinelli's pattern — `Scan Document` → `Wait` → `Get Contents of Folder` → `Filter Files` (newest) → `Save File`/`Move File`. Destination determinism is the thing to verify on-device.
- *Actions-app variant (recommended)*: the free, well-maintained [Actions app](https://apps.apple.com/us/app/actions/id1586435171) by Sindre Sorhus provides **"Scan Documents — Scans one or more documents using the system document scanner"** with a "Use PDF" toggle; per its own docs "the resulting images are copied to the clipboard. Add the 'Wait to Return' and 'Get Clipboard' actions after this one" ([canonical action list gist](https://gist.github.com/sindresorhus/fbba65a774fb9da915e624807a02a6d2)). Chain: `Scan Documents (Actions)` → `Wait to Return` → `Get Clipboard` → `Save File`. The `Save File` action with "Ask Where to Save" off lets you **Replace** the default `Shortcuts` folder with any iCloud Drive folder via the picker ([EasyOSX](https://easyosx.net/2023/01/16/copy-a-file-in-the-shortcuts-app/); [Apple Community](https://discussions.apple.com/thread/252246641)).

**Lock-state**: lock-screen widget taps require authentication ("widget button clicks trigger a login" — [MPU forum](https://talk.macpowerusers.com/t/shortcut-wont-run-unless-iphone-is-unlocked/34878), [Gadget Hacks](https://ios.gadgethacks.com/how-to/you-can-run-shortcuts-right-from-your-iphones-lock-screen-here-are-6-ways-do-0384270/)). With Face ID, Action-Button-while-raising effectively self-unlocks; count stays at 2 deliberate actions. Alternative triggers: Lock Screen button, Control Center control, Back Tap — all launch the same shortcut.

**Mac side / inbox plumbing** (read-on-demand semantics):
- The inbox must live in iCloud: `~/Library/Mobile Documents/com~apple~CloudDocs/studies/inbox/`, with `ln -s` from `~/studies/inbox` (reading through a symlink into the iCloud container is plain filesystem behavior — inferred, uncontroversial; the reverse — symlinking out of iCloud — does not sync).
- Since macOS Sonoma, iCloud Drive uses **dataless files, no `.icloud` stubs**: "there are no stubs any more, instead the files simply become dataless… [a dataless file] can be manually downloaded … or **by any operation that needs to access their data**" ([Eclectic Light: Sonoma changed iCloud Drive radically](https://eclecticlight.co/2023/10/25/macos-sonoma-has-changed-icloud-drive-radically/), [Dataless files arrive](https://eclecticlight.co/2023/10/29/last-week-on-my-mac-dataless-files-arrive/)). So: **`ls` (stat) does not materialize a file; any read of its data does** — the on-demand consumer will trigger download just by reading, *once the file's metadata has synced down and it appears in the directory at all*.
- With **Optimize Mac Storage OFF**, iCloud Drive "is a replicating FileProvider, and maintains complete local copies of all files" — i.e., new arrivals download eagerly ([Eclectic Light: Understanding and testing iCloud, Apr 2026](https://eclecticlight.co/2026/04/06/understanding-and-testing-icloud/)). Sync timing per the same source: "Syncing isn't immediate … but it should occur within a couple of minutes when there are good connections"; a 1 MB test file "should appear almost instantly."
- Belt-and-braces nudge: **`brctl download <path>` — verified working on this macOS 26.4.1 machine** (absent from `brctl`'s help but present in `man brctl` and functional). Sequoia+ also added Finder **pinning ("Keep Downloaded")**, implemented as the `com.apple.fileprovider.pinned` xattr, settable via `xattr` ([Eclectic Light: pinning](https://eclecticlight.co/2024/09/30/how-icloud-has-changed-in-sequoia-pinning-and-more/)) — pin the inbox folder; whether new arrivals inherit the pin is an empirical item.

**Fragility**: iCloud sync variance (incl. rare throttling — [Eclectic Light](https://eclecticlight.co/2024/02/22/icloud-does-throttle-data-syncing-after-all/)); phone Low Power Mode; the native action's folder-targeting quirk; Actions-app clipboard hand-off (large multi-page scans through the clipboard — test).

### Flow B — Finder "Import from iPhone" (Continuity Camera)

**Documented.** In Finder: "Control-click the desktop or a folder in a Finder window", possibly via the "Import from iPhone or iPad" submenu → Take Photo / Scan Documents. Requirements: same Apple Account, both radios on, within 30 ft/10 m ([Apple mac-help guide](https://support.apple.com/guide/mac-help/insert-photos-documents-iphone-ipad-mchl9aebdc99/mac); [Apple 102332](https://support.apple.com/en-us/102332) — the latter states the scan "detects the edges of the document and **autocorrects any skewing**"). The phone-side UI opens **automatically**: "your iPhone will magically awaken and open the camera" ([XDA](https://www.xda-developers.com/continuity-camera/)); the scanner "captures each page automatically as you position it," and "tapping Save on the iPhone places a **PDF named Scanned Document** into the chosen folder"; Take Photo yields a JPEG; scan modes Color/Grayscale/B&W/Photo ([MacMost](https://macmost.com/how-to-use-your-iphone-as-a-scanner-for-your-mac.html)). Whether the phone must be *unlocked* first is not stated in any doc retrieved — empirical item.

**Steps counted** (Finder window pre-parked on `~/studies/inbox`): ① right-click empty area → ② Import from iPhone → Scan Documents → phone lights up, Auto mode captures the page (0 taps; +1 "Keep Scan" only in manual mode) → ③ tap Save. **3 actions, ~15–25 s (estimate), file lands directly in the target local folder** — no sync layer at all.

**Automation hooks** (to collapse Mac side to one hotkey):
- No documented keyboard shortcut; System Settings App Shortcuts can only bind menu-bar items, and Apple documents the Finder entry point as the *context* menu only (File-menu presence on current macOS: unverified — checklist).
- Working **Keyboard Maestro / AppleScript UI-scripting recipe** (Dec 2018, re-validated on Big Sur 2021): deselect Finder selection, then `tell application process "Finder" … set _selection to value of attribute "AXFocusedUIElement" … tell _selection to perform action "AXShowMenu"`, then keystroke-navigate to the menu item, with delays ([Keyboard Maestro forum](https://forum.keyboardmaestro.com/t/ideas-to-trigger-continuity-camera-import-from-iphone/12295)). Known bug in the same thread: when driven by *simulated* AppleScript keystrokes, "the camera activates … but it never shows up on my Mac. When I do the same keystrokes using the actual keyboard, it works" — must re-verify on macOS 26.
- macOS Shortcuts has no documented Continuity-Camera import action; whether Mac Shortcuts' "Take Photo" action exists/uses the iPhone is unverified (checklist).

**Quality**: same VisionKit scan engine as Flow A (deskew + contrast). Output PDF page pixel dimensions undocumented (checklist: `pdfimages -list`). "Take Photo" import resolution undocumented; one Apple-Communities thread reports Continuity Camera *stills* at 1920×1440 vs 4032×3024 native ([discussions thread](https://discussions.apple.com/thread/254333013) — context ambiguous, likely webcam-pipeline stills; **treat Take-Photo-import resolution as unknown**, prefer Scan Documents regardless).

### Flow C — Desk-stand iPhone as persistent document camera

**Documented.** For third-party/CLI consumption, Continuity Camera webcam formats are: "three 16:9 formats — from 640×480 to 1080p — and one 4:3 format: **1920×1440**", 30/60 fps; **Desk View is a separate AVCapture device** (`AVCaptureDeviceType.deskViewCamera`, `companionDeskViewCamera`) with exactly **one format: 420v 1920×1440 @ ≤30 fps** ([WWDC22 session 10018](https://developer.apple.com/videos/play/wwdc2022/10018/), [WWDC Notes](https://wwdcnotes.com/documentation/wwdcnotes/wwdc22-10018-bring-continuity-camera-to-your-macos-app/), [AVFoundation docs](https://developer.apple.com/documentation/AVFoundation/supporting-continuity-camera-in-your-macos-app)). Auto-selection wants the phone near the Mac, stable, landscape, screen off; the feed **pauses when the phone is unlocked**; notifications are suppressed while in use as webcam ([Apple 102546](https://support.apple.com/en-us/102546), [mac-help guide](https://support.apple.com/guide/mac-help/use-iphone-as-a-webcam-mchl77879b8a/mac)). Portrait/odd orientations produce cropped, limited format lists in OBS ([OBS forum report](https://obsproject.com/forum/threads/iphone-camera-source-continuity-camera-only-has-ridiculous-cropped-resolutions-selectable-when-used-in-portrait-orientation.161378/)) — relevant because a doc-cam points *down*. Heat/battery: ~30–40 %/hour drain reported, phone runs hot, and **iPhones pause MagSafe (often even wired) charging during Continuity Camera** ([Carlos Becker](https://carlosbecker.com/posts/continuity-camera/), [TidBITS](https://tidbits.com/2024/05/25/iphones-pause-magsafe-charging-during-continuity-camera/), [9to5Mac](https://9to5mac.com/2024/05/31/psa-magsafe-probably-isnt-charging-your-iphone-when-using-continuity-camera/)). For on-demand single grabs (connect→shoot→disconnect) heat is a non-issue but each grab pays connect+warmup latency (inferred; measure).

**Empirically verified on this Mac today**: `ffmpeg -f avfoundation -list_devices true -i ""` lists `Shannon's iPhone 16 Camera` and `Shannon's iPhone 16 Desk View Camera` as ordinary AVFoundation video devices — so **yes, plain CLI tools see Continuity Camera**, wirelessly, without any app. [imagesnap](https://github.com/rharder/imagesnap) (`brew install imagesnap`; `-l` list, `-d <name>` select, `-w` warmup) uses the same AVFoundation enumeration.
Capture recipe: `imagesnap -w 3 -d "Shannon's iPhone 16 Camera" ~/studies/inbox/page-$(date +%s).jpg` or `ffmpeg -f avfoundation -framerate 30 -video_size 1920x1440 -i "Shannon's iPhone 16 Camera" -frames:v 1 out.png`, bound to a hotkey via Shortcuts (Run Shell Script → `shortcuts run`, CLI verified present) / Raycast / skhd. Post-process toward scan-grade: `magick in.png -colorspace gray -deskew 40% -contrast-stretch 1%x1% out.png` (standard tooling; effectiveness = empirical).

**Verdict**: 1-action capture, but 1920×1440 ≈ 169 ppi across a Letter page (inferred: 1440 px / 8.5 in), no true deskew, connection persistence unproven → experiment only. **Desk View: reject** for text (single warped 1920×1440 format; "At a push, it will show your desk … don't expect wonders" — [David Lewis review](https://talkingtechandaudio.com/blog/continuity-camera-belkin/); [Apple Desk View doc](https://support.apple.com/en-us/121541)).

### Flow D — AirDrop

Auto-accept + auto-save with no Mac-side dialog when both devices share the Apple Account; files land in `~/Downloads`, not configurable ([Apple mac-help AirDrop](https://support.apple.com/guide/mac-help/use-airdrop-to-send-items-to-nearby-devices-mh35868/mac), [iPhone AirDrop guide](https://support.apple.com/guide/iphone/use-airdrop-to-send-items-to-nearby-devices-iphcd8b9f0af/ios), [SlashGear](https://www.slashgear.com/1668503/mac-airdrop-files-location/)). 5 phone actions, raw un-deskewed photo, needs a Downloads→inbox mover (Folder Action/launchd — a watcher). Dominated by A/B.

### Flow E — iCloud Photos + osxphotos

Capture is 2 actions, but the pipeline (iPhone Photos upload → Photos.app download → [osxphotos](https://github.com/RhetTbull/osxphotos) export poll) has minutes-scale variance and heavyweight setup; output is an unprocessed photo. Dominated.

### Flow F/G — Files-app scan / third-party scanners

Files-app scan is the same scanner with 4 taps and no setup ([Apple 108963](https://support.apple.com/en-us/108963)) — the manual fallback when the shortcut breaks. Genius Scan auto-export needs the Ultra plan and exports to a fixed `iCloud Drive/Genius Scan` folder, triggering on return-to-list/app-exit ([Genius Scan help](https://help.geniusscan.com/exporting-and-sharing/export-destination-and-shortcuts/auto-export-rules-and-configuration)); Scanner Pro auto-uploads to a fixed `Scanner by Readdle` folder ([Readdle KB](https://support.readdle.com/scannerpro/connect-to-cloud-storage/auto-upload-scans-to-cloud-storage)). Neither beats Flow A on steps; both add a paid dependency. Skip.

## 4. Automation glue (exact parts list)

**#1 build (Flow A):**
1. Phone: install **Actions** (free). Shortcut "Scan to Inbox": `Scan Documents [Use PDF: per taste — Grayscale/B&W for math]` → `Wait to Return` → `Get Clipboard` → `Save File [Service: iCloud Drive; Ask Where to Save: Off; Destination: replace "Shortcuts" with studies/inbox; Overwrite: Off]`. (Try the native `Scan Document` action first — zero dependencies — and keep it only if its destination proves deterministic.)
2. Phone: Settings > Action Button → Shortcut → "Scan to Inbox". Optionally also add as Lock Screen control / Back Tap.
3. Mac (one-time): `mkdir -p ~/Library/Mobile\ Documents/com~apple~CloudDocs/studies/inbox && ln -s ~/Library/Mobile\ Documents/com~apple~CloudDocs/studies/inbox ~/studies/inbox`; System Settings > Apple ID > iCloud Drive > **Optimize Mac Storage: Off** (forces replicating mode = eager downloads); optionally Finder right-click inbox → "Keep Downloaded".
4. Consumer command prologue: `find "$INBOX" -type f -flags +dataless -exec brctl download {} \;` then short retry loop (≤60 s) if the expected page count hasn't appeared.

**#2 build (Flow B):** nothing to install. Optional hotkey: Keyboard Maestro macro per the forum recipe (open/focus inbox Finder window → deselect → `AXShowMenu` → arrow/keystroke to Import from iPhone → Scan Documents, with 0.3–0.5 s delays).

**#3 build (Flow C):** `brew install imagesnap`; Mac Shortcut wrapping the capture + `magick` post-process, bound to a hotkey; phone in stand, plugged in, screen locked.

## 5. Empirical test checklist (documentation cannot settle these)

1. **iCloud latency distribution**: 20 Action-Button scans at the desk; timestamp phone-Save vs file readable on Mac (`stat` loop). Record p50/p90/max; test with Mac display asleep, and with phone on Wi-Fi vs 5G. → decides #1 vs #2.
2. **Materialization semantics on macOS 26**: with Optimize Mac Storage ON and OFF — does the new PDF arrive already materialized? does `cat` on a dataless file block-and-download? does `brctl download` accelerate? do files *added later* to a pinned folder inherit `com.apple.fileprovider.pinned`?
3. **Native "Scan Document" action**: where exactly does it save (last-open Files folder? picker?); can it run from Action Button with phone locked (Face ID glance) — total taps; does the follow-up `Get Contents of Folder`/`Filter Files` pattern reliably fetch the newest scan.
4. **Actions-app "Scan Documents"**: current output path (clipboard vs direct variable — the docs' clipboard note may be stale); multi-page PDF through clipboard; end-to-end tap count.
5. **Scan output resolution**: run one Finder scan and one Shortcuts scan of a Letter page; `pdfimages -list` the PDFs — confirm page images land ~2000–3300 px long edge (vs Claude's 2576 px native ceiling); check Grayscale vs Color file sizes (iOS 18 defaults to color).
6. **Finder import details**: is unlock required before the phone's scan UI appears; exact output filenames; "Take Photo" JPEG dimensions (EXIF) — is it 4032×3024 or 1920×1440; **does Finder's menu-bar File menu contain "Import from iPhone"** (would enable an App-Shortcuts keybinding without UI scripting); does the KM `AXShowMenu` recipe still work on macOS 26, and does the simulated-keystroke no-file bug reproduce.
7. **Flow C feasibility**: `imagesnap -l` sees the iPhone?; capture with phone locked + screen off in a stand pointing down (orientation/crop behavior); actual max still size obtainable via ffmpeg/imagesnap (expect ≤1920×1440); per-grab latency; focus/exposure warmup frames needed; thermal behavior over a 2 h session of periodic grabs; Desk View one-page legibility test (expect fail).
8. **Mac Shortcuts "Take Photo" action**: does it exist on macOS 26 and can it select the iPhone as source (would give a native hotkey path with no UI scripting)?
9. **AirDrop control**: confirm same-Apple-ID auto-accept is dialog-free on macOS 26 and files land in `~/Downloads` (only matters if D is ever used).
